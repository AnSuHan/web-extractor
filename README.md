# web-extractor

화면과 동작에서 **구현 사양을 뽑아내는** 프롬프트 작업대.

`prompt.md`에 적힌 목표 — *"이미지 → 완벽한 프론트 구현 프롬프트 작성 + 네비게이팅 테스트"* — 를
브라우저에서 쓰는 도구로 만든 것입니다.

## 무엇을 하는가

| 탭 | 입력 | 출력 |
|---|---|---|
| **수집** | 대상 URL + 범위 | 내 브라우저 세션으로 돌며 모은 API 응답·HTML 구조·백엔드 단서 |
| **UI 재구성** | UI 스크린샷 | 픽셀 퍼펙트 재구성을 강제하는 완성형 프롬프트 |
| **네비게이팅 테스트** | 대상 URL + 조사 범위 | 브라우저 에이전트(Playwright MCP 등)가 실제로 눌러보며 기능 명세·클릭 플로차트를 쓰게 하는 조사 프롬프트 |
| **API 역설계** | DevTools HAR 캡처 | 엔드포인트 인벤토리 + API 클라이언트 생성 프롬프트 |

**수집 → 분석은 전부 API 키 없이 돌아갑니다.** 엔드포인트 그룹핑, 데이터 모델 추론,
백엔드 스택 지문은 모두 결정적 계산입니다. 만들어진 프롬프트는 복사해서 아무 에이전트에나
붙여넣으면 되고, 원하면 Anthropic 키를 넣어 이 페이지에서 바로 실행할 수도 있습니다(선택).

## 수집기 (Chrome 확장)

`collector/` 폴더가 MV3 확장입니다. **런처가 이미 로드해서 띄워 줍니다** — 따로 설치할 것이 없습니다.

1. `run.bat` 으로 연 브라우저에서 대상 앱에 **평소처럼 직접 로그인**
2. 같이 열린 앱의 **수집** 탭에서 시작 URL·범위를 넣고 **수집 시작**
3. 처음 시작할 때 그 사이트 접근 권한을 한 번 묻습니다 — 허용하면 새 탭이 한 페이지씩 돕니다
4. 순회가 끝나면 **CSS·JS·폰트 본문**을 이어서 받고, 페이지마다 **전체 화면 캡처**를 남깁니다
5. **결과 가져오기** 로 바로 분석 (또는 확장 팝업의 **결과 파일로 저장** 으로 `.json` 보관)

### 링크로 갈 수 없는 화면 — 수동 탐색 모드

로그인 후 화면, 버튼으로만 열리는 모달, 폼 제출 결과는 `<a href>` 순회로 도달할 수 없습니다.
**수동 탐색 모드**로 시작하면 확장이 자동으로 이동하지 않고, **사용자가 직접 클릭하며 여는
화면과 요청을 그대로 기록**합니다. 다 돌았으면 **중단**을 누르면 됩니다 — 그때 정적 리소스를
받고 마무리합니다.

> **앱 자체가 확장 페이지(`chrome-extension://<id>/app/`)로 열립니다.** 그래서 권한 요청도
> 앱 안에서 처리되고, 설정부터 시작·진행·결과까지 한 화면에서 끝납니다.
> 확장 팝업에는 어디서나 닿아야 하는 것만 남겼습니다 — 앱 열기, 결과 저장, 중단, 기록 비우기.
>
> 개발 서버(`npm run dev`)로 연 `localhost` 페이지에서는 Chrome 이 권한 창을 띄워주지 않습니다.
> 그때는 앱이 **설정만 확장으로 넘기는** 다리 모드로 동작합니다.

### 왜 차단되지 않는가

봇 탐지 우회 코드는 들어 있지 않습니다. 대신 탐지할 대상이 되지 않습니다.

- **진짜 브라우저, 진짜 세션.** headless 지문도, 자동화 플래그도, 위조 User-Agent 도 없습니다.
  서버 입장에서는 로그인한 사용자가 페이지를 넘기는 것과 구분되지 않습니다.
  (스텔스 플러그인으로 지문을 위조하는 쪽이 오히려 요즘 WAF 에 더 잘 걸립니다.)
- **페이지 안에서 가로챕니다.** 앱 자신의 `fetch`/`XHR` 을 감싸므로 CORS 가 응답 본문을
  가리지 않습니다. 프록시도 루트 인증서 설치도 필요 없습니다.
- **정중하게 돕니다.** 동시 요청 1개, 페이지 간 기본 1.5초, robots.txt 의 `Crawl-delay` 가
  더 느리면 그쪽을 따릅니다.

### 안전 설계

- **버튼을 누르지 않습니다.** 순회는 `<a href>` 로 발견한 URL 만 GET 으로 방문합니다.
  삭제·결제·상태 변경을 우발적으로 실행할 수 없는 구조입니다.
- **권한은 오리진 단위.** `<all_urls>` 를 요구하지 않고, 시작할 때 그 사이트에 대해서만
  권한을 요청한 뒤 끝나면 스크립트 등록을 해제합니다.
- **토큰 값을 가립니다.** Authorization·Cookie 류는 이름만 남고 값은 `<redacted:N chars>` 가
  됩니다. 저장 파일에 실토큰이 남지 않습니다.
- **폼 입력값은 수집하지 않습니다.** 필드의 이름·타입·제약만 가져옵니다.
- 시작 전 **수집 권한이 있다는 확인**에 체크해야 버튼이 활성화되고, 그 다음 브라우저가
  해당 사이트 접근 권한을 한 번 더 묻습니다.
- 정적 리소스도 **권한을 받은 오리진에서만** 받습니다. 외부 CDN 은 사용자가 따로 허용해야
  받아 오고, 허용하지 않으면 URL 만 남습니다.

### 한계

- 브라우저가 자동으로 붙이는 **쿠키는 후킹에 보이지 않습니다.** 쿠키 세션이면 인증 헤더가
  비어 보일 수 있습니다.
- **교차 출처** 응답 헤더는 CORS 가 일부만 노출합니다. API 가 다른 도메인이면 서버 지문이 얇습니다.
- WebSocket·SSE·서비스 워커 내부 요청은 잡히지 않습니다.
- 링크로 도달할 수 없는 화면(버튼으로만 열리는 모달 등)은 자동 순회가 못 갑니다. 그 부분은
  **수동 탐색 모드**로 직접 돌면 그대로 수집됩니다.
- **외부 CDN 리소스**는 권한 밖이라 본문을 받지 못하고 URL 만 남습니다. 앱의 *화면·리소스* 뷰에서
  **그 오리진들 권한을 허용하면 마저 받아 옵니다.**
- 화면 캡처는 디버거 프로토콜을 씁니다(`captureVisibleTab` 은 `<all_urls>` 를 요구해서 쓰지
  않습니다). 그래서 수집 탭 위에 **"디버깅하고 있습니다" 알림 바**가 뜹니다 — 숨기지 않습니다.
  세로로 아주 긴 페이지는 8000px 에서 자릅니다.

## 수집 결과로 무엇이 나오는가

전부 `src/lib/infer.ts` 의 결정적 계산입니다.

- **화면 캡처** — 페이지마다 **접힌 부분까지 전체**를 찍은 JPEG. 골라서 **UI 재구성 탭으로
  바로 보낼 수 있습니다** — 그 탭이 요구하는 시각 기준이 이것입니다.
- **정적 리소스 본문** — CSS·JS·폰트(옵션으로 이미지). HTML 만으로는 화면을 되살릴 수 없고,
  이것들은 페이지가 직접 받기 때문에 요청 후킹에 잡히지 않습니다. 그래서 순회가 끝난 뒤
  확장이 한 번 더 받아 둡니다. `?v=` 같은 캐시버스터만 다른 URL 은 하나로 접습니다.
- **커버리지** — 링크로 발견한 URL 수와 실제 방문 수. **못 간 화면이 있으면 그대로 적습니다**
  (상한에 걸려 멈췄는지도 함께). 캡처가 사이트 전체인 척하지 않습니다.
- **사이트맵** — 방문한 URL 을 경로 트리로 접은 것
- **엔드포인트** — `/orders/8821` 과 `/orders/9902` 를 `/orders/{id}` 로 묶고, 요청·응답 본문 샘플 첨부
- **데이터 모델** — 응답 JSON 에서 되짚은 TypeScript 인터페이스.
  `?`(일부 응답에만 존재)와 `| null`(값이 null)을 **구분**하고, `date-time`/`uuid`/`email`/`url`
  형식과 예시 값을 주석으로 답니다. 모든 샘플이 null 인 필드는 `unknown` 으로 두고 그렇다고 적습니다.
- **백엔드 추론** — API 스타일(REST/GraphQL/RPC), 경로 접두사, 인증 방식, 스택 지문.
  **모든 주장에 근거를 함께 적습니다** (`Node.js / Express ← x-powered-by: Express`).
- **폼·컨트롤** — 필드 제약과 버튼 목록

수집한 캡처는 **"이 캡처로 프롬프트 만들기"** 로 API 역설계·네비게이팅 테스트 탭에 그대로 넘어갑니다.

## 결과물로 내보내기

프롬프트만 만드는 게 아니라, **바로 쓸 수 있는 두 가지 산출물**을 뽑습니다. 둘 다 브라우저
안에서 조립하며 서버로 나가는 것은 없습니다.

### 프론트 — 정적 사이트 `.zip`

압축을 풀고 `index.html` 을 열면 그 화면이 뜹니다. 서버가 필요 없습니다.

```
index.html                 # 방문한 화면마다 한 파일 (/supportGuide/main → supportGuide/main.html)
static/css/*.css           # 받아 둔 스타일 — url(...) 참조까지 로컬 경로로 재작성
static/js/*.js
static/fonts/*.woff2
_screenshots/*.jpg         # 원본 화면 — 재현 결과를 눈으로 대조할 기준
README.md                  # 무엇이 들어 있고 무엇이 빠졌는지
```

`<link>`·`<script>`·`<img>`·`srcset`·인라인 `style`·CSS 안의 `url()`·`@import` 를 전부 로컬
상대 경로로 바꿉니다. `<base>` 태그는 제거합니다(남겨 두면 모든 상대 경로가 원래 사이트로
끌려갑니다). **받지 못한 것은 원래 절대 URL 로 남깁니다** — 온라인이면 그대로 뜨고, 조용히
깨지지 않습니다. 이미지까지 오프라인으로 담으려면 수집할 때 *이미지까지 받기* 를 켜세요.

### 백엔드 — 구현 명세 `.md`

에이전트가 그대로 읽고 구현할 수 있는 문서입니다. 목차는 고정입니다.

```
0. 수집 범위 (커버리지 포함)   5. 엔드포인트 상세 — 요청·응답 본문 샘플
1. API 스타일 · 경로 접두사    6. 데이터 모델 (TypeScript 인터페이스)
2. 인증 (근거 포함)            7. 폼 — 서버가 받아야 하는 입력
3. 스택 지문                   8. 구현 순서 제안
4. 엔드포인트 목록 (표)        9. 관찰하지 못한 것
```

**광고·분석 호출은 빼고 자기 오리진만** 놓고 다시 추론합니다(섞이면 `/collect`, `/rmkt` 가
이 사이트의 API 인 것처럼 보입니다). 마지막 절에 **확인하지 못한 것**을 그대로 남기는 것이
이 문서의 핵심입니다 — 빈 곳을 모르고 지어내는 것이 가장 나쁩니다.

## 실행

**`run.bat` 을 더블클릭하세요** (macOS·Linux 는 `./run.sh`). 그게 전부입니다.

런처가 알아서 합니다:

1. 의존성 설치 — 없을 때만
2. 앱을 확장 안(`collector/app/`)으로 빌드 — 소스가 바뀌었을 때만
3. **collector 확장을 로드한 브라우저를 띄우고, 앱을 확장 페이지로 엽니다**

평소 실행에는 개발 서버가 필요 없습니다. 확장을 로드할 수 있는 브라우저가 하나도 없을 때만
개발 서버로 물러나 분석 기능이라도 쓸 수 있게 합니다.

미리 설치해 둬야 하는 건 없습니다. Node 가 없으면 `.tools/` 안에 받아서 쓰고,
시스템 PATH 나 레지스트리는 건드리지 않습니다. 지우고 싶으면 폴더째 삭제하면 끝입니다.

### 브라우저는 자동으로 고릅니다

**Chrome 136+ 는 `--load-extension` 을 막았고, 153 에서는 우회 플래그마저 사라졌습니다.**
그래서 런처는 확장을 로드할 수 있는 브라우저를 순서대로 시도합니다.

```
이미 받아둔 Chrome for Testing  →  Edge  →  Chrome  →  Chromium
```

띄우는 것만으로는 알 수 없어서(플래그를 받아들이는 척하고 무시합니다),
**프로필을 읽어 확장이 실제로 등록됐는지 확인**합니다. 등록이 프로필에 쓰이기까지
10초 안팎 걸리므로 넉넉히 기다립니다. 실패하면 다음 후보로 넘어가고, 후보가 다 떨어지면
Chrome for Testing 을 자동으로 받아옵니다(약 150MB, 처음 한 번).

통과한 브라우저와 확장 ID 는 `.tools/browser.json` 에 적어 둡니다. **다음 실행부터는
후보를 훑지 않고 그 브라우저로 곧장 앱을 열기 때문에, 전용 프로필이 지워지지 않습니다** —
대상 사이트에 한 번 로그인해 두면 그대로 남습니다. (후보를 새로 훑을 때는 판정이 오염되지
않도록 프로필을 비웁니다.)

### 수동으로 하고 싶다면

```bash
npm install
npm start        # 런처 (run.bat 과 같음)
npm run dev      # 개발 서버만 — localhost 는 다리 모드(시작은 확장 팝업에서)
npm run build    # collector/app/ — 확장 안에 들어가는 앱
npm run build:web    # dist/ — 웹에 올리는 빌드 (아래 "웹에 올려서 쓰기")
npm run release:web  # dist/assets 를 GitHub 릴리스로 (호스팅이 큰 파일을 못 받을 때)
```

소스를 고친 뒤에는 `run.bat` 을 다시 실행하면 바뀐 부분만 다시 빌드해서 띄웁니다.

> **`collector/` 안의 확장 코드를 고쳤다면 `manifest.json` 의 `version` 도 올리세요.**
> 브라우저를 껐다 켜도 서비스 워커가 옛 코드를 그대로 붙잡고 있는 경우가 있습니다
> (버전이 바뀌면 확실히 새로 설치됩니다).

### 수집까지 되는 이유

일반 웹페이지에는 `chrome.*` 가 없어 수집을 시작할 수 없습니다. 우회가 아니라 MV3 의 정식
통로인 **`externally_connectable`** 을 씁니다 — 매니페스트에 배포 도메인을 등록해 두면 그
사이트의 페이지가 확장과 직접 메시지를 주고받습니다.

```
배포 사이트  ──(설정·시작 요청)──▶  확장 서비스 워커
     ▲                                    │
     └──(상태·진행·결과 조각)───────────┘
```

- **확장 ID 를 고정**했습니다(`manifest.json` 의 `key`). 압축 해제 확장의 ID 는 폴더 경로에서
  파생돼 PC 마다 달라지는데, 배포된 앱이 확장을 지목하려면 고정이어야 합니다.
- **시작만 확장 창에서 한 번 승인**합니다. 사이트 접근 권한 요청은 확장 컨텍스트의 사용자
  제스처를 요구하고, 웹페이지가 조용히 수집을 켤 수 있어서도 안 되기 때문입니다.
  배포 사이트에서 *수집 시작* 을 누르면 확장이 설정이 채워진 창을 열고, 거기서 승인하면
  그 뒤의 진행·결과·분석·내보내기는 전부 배포 사이트에서 이어집니다.
- 외부에서 받는 메시지는 `ping`·`status`·`export*`·`prefill`·`stop`·`reset`·`assets-more` 로
  제한했습니다. 페이지 스냅샷·네트워크 기록은 **절대 받지 않습니다** — 받으면 웹페이지가
  가짜 수집 결과를 밀어 넣을 수 있습니다.
- 캡처가 수십 MB 라 결과는 조각으로 옮깁니다(`export-begin` → `export-chunk` → `export-end`).

확장이 없는 방문자에게는 수집 UI 대신 안내가 뜨고, 캡처 `.json` 을 올려 분석·프롬프트·
정적 사이트 `.zip`·백엔드 명세 `.md` 를 그대로 쓸 수 있습니다.

### 배포하기

```bash
npm run build:web      # dist/ — 앱 + 의존성 없는 정적 서버(server.mjs) + package.json
npm run release:web    # (선택) 자산을 GitHub 릴리스에 올리고 dist/assets-source.json 생성
```

`dist/` 를 그대로 올리면 끝입니다(`start: node server.mjs`, `PORT` 환경변수 사용).
**파일을 인라인으로만 올릴 수 있는 호스팅**이라 500KB 짜리 번들을 밀어 넣기 어렵다면
`release:web` 으로 자산을 공개 릴리스에 두고, 작은 파일들만 배포하세요 — 서버가 부팅할 때
한 번 받아 디스크에 캐시합니다.

하위 경로(`/web-extractor`)로 프록시되는 경우도 고려돼 있습니다. 프록시가 접두사를 떼고
넘기면 서버가 알 수 없으므로, `index.html` 이 자기 위치를 보고 `<base>` 를 잡습니다.

> 새 도메인에 올렸다면 `collector/manifest.json` 의 `externally_connectable.matches` 에 그
> 오리진을 추가하고 **버전을 올려** 확장을 새로 로드해야 연결됩니다.

## 설계 노트

### UI 재구성 — 왜 옵션이 프롬프트를 바꾸는가

원본 프롬프트는 "절대 재디자인하지 마라"를 20가지 방식으로 반복하는 강한 제약 문서입니다.
그 강도를 유지하되, 실제로는 프로젝트마다 달라지는 부분(프레임워크, 스타일 시스템,
반응형 필요 여부, 충실도 허용치)이 있어서 그 축만 옵션으로 뺐습니다.

- **충실도**를 `픽셀 퍼펙트`로 두면 "31px를 32px로 바꾸지 마라"가 그대로 들어가고,
  `균형`으로 낮추면 2px 미만 편차의 4px 스케일 정규화를 허용하되 **전부 주석으로 남기게** 합니다.
  조용한 정규화가 아니라 기록되는 정규화입니다.
- Tailwind를 고르면 "스케일 단계가 안 맞으면 `p-[31px]` 같은 임의값을 쓰고, 가까운 단계로
  반올림하지 마라"가 추가됩니다. 이게 Tailwind에서 픽셀 퍼펙트가 깨지는 가장 흔한 경로입니다.
- 이미지를 2장 이상 올리면 "같은 인터페이스의 다른 상태이니 하나의 컴포넌트 트리로 합쳐라"가
  들어갑니다. 안 넣으면 화면 수만큼 독립적인 결과가 나옵니다.

### 네비게이팅 테스트 — 해피패스 편향 보정

소스 없이 UI만 보고 명세를 복원한 사례(Thoughtworks의 Odoo CRM 재구성)에서 보고된
가장 큰 한계는 **에이전트가 지나치게 단순한 해피패스만 찾아낸다**는 점이었습니다.
그래서 이 프롬프트는 그 실패 모드를 정면으로 막습니다.

- **4-pass 강제**: 지도 그리기 → 접근성 트리로 요소 열거 → 실제 조작 → 작성.
  픽셀이 아니라 접근성 트리에서 요소를 세게 해서, 접혀 있거나 화면 밖에 있는 컨트롤도 잡습니다.
- **화면당 할당량**: 잘못된 입력 분기 1개, 거부되는 분기 1개, 라벨만 봐선 모르는 컨트롤 1개,
  연동 동작(A를 바꾸면 B가 바뀜) 1개. 없으면 "없다"고 명시하고 무엇을 시도했는지 쓰게 합니다.
- **`## Unverified` 분리**: 확인 못 한 것을 조용히 빼지도, 지어내지도 못하게 합니다.
- `'표준적인'`, `'일반적인'`, `'예상대로'` 같은 서술을 금지합니다 — 관찰한 것을 쓰게 합니다.

안전 규칙(스테이징 우선, 파괴적 동작은 확인 다이얼로그까지만, 인증·레이트리밋 우회 금지,
개인정보·자격증명 비기록)이 프롬프트에 함께 들어갑니다.

### API 역설계 — HAR은 브라우저에서 파싱합니다

`src/lib/har.ts`가 업로드 없이 브라우저 안에서 HAR을 읽고:

- 정적 자산(이미지/CSS/JS/폰트)을 걸러냅니다 — API 역설계에는 잡음입니다.
- 경로의 숫자·UUID·해시 세그먼트를 `{id}` / `{uuid}` / `{hash}`로 일반화해
  `/orders/8821`과 `/orders/9902`를 **한 엔드포인트로 묶습니다.**
- 본문 샘플을 구조는 유지한 채 줄입니다(배열은 앞 2개, 긴 문자열은 절단).
- `token` / `password` / `authorization` 류 키의 값을 `<redacted:N chars>`로 가립니다.
  캡처된 실제 토큰이 프롬프트를 타고 모델에 흘러가지 않게 하기 위한 것입니다.

## 데이터 취급

- 백엔드가 없습니다. 이미지·HAR·API 키는 **어떤 서버로도 전송되지 않습니다.**
- 옵션과 보관함은 이 브라우저의 `localStorage`에만 남습니다.
- API 키를 넣고 "실행"을 누를 때만, 브라우저가 Claude API로 **직접** 요청을 보냅니다
  (`dangerouslyAllowBrowser`). 확장 페이지에서 나가는 요청이라 `manifest.json` 의
  `host_permissions` 에 `api.anthropic.com` 하나만 올려 두었습니다.
  이 방식은 키가 기기를 떠나지 않는 대신,
  이 페이지의 스크립트가 키를 읽을 수 있다는 뜻이기도 합니다. 공용 PC에서는 사용 후 지우세요.
- 공개 배포 시 키를 남에게 노출하고 싶지 않다면, API 호출만 서버 프록시로 옮기고
  `src/lib/claude.ts`의 `baseURL`을 그 프록시로 바꾸면 됩니다.
